# 병종 행동·모션 표현 계약

2026-10-08 KST · Stage 01 UI 파일럿과 병행하는 공통 표현 기준입니다. [행동 설계도](06-troop-action-contract.svg)는 개념도이며, 새 Stage 01의 맵 좌표·방어 구역 형태·지형·카메라를 확정하지 않습니다. 최종 맵 아트, 40개 전장 확장, 컷씬은 이 문서의 범위에 포함하지 않습니다.

**R1 후속 닌자 지시:** 총괄을 통해 직접 사용자 지시인 거점 공격·가장 강한 적 암살·소모성 역할과 L2 폭탄, L5 실제 3회 타격 후 폭탄, L8 파편 방향을 전달받았습니다. 아래 타워 전용 설명은 앞선 구현·검증의 기준 기록이며 최신 역할 제한으로 적용하지 않습니다. 움직이는 표적, 연속 실제 타격, 설치, 소모, 지연 폭발의 정확한 기능 사건은 기능·밸런스팀의 REV4 계약 확인 후 연결합니다. 모션팀이 표현 타이머로 추가 타격·폭발·피해를 생성하지 않습니다.

## 확정 방향과 기능 소유권

- 장도병은 아군 타워 방어 구역 안에서 경계합니다. 인식한 **기지 공격자**에게 구역 내부의 안전한 경로로 접근하고, 표적을 잃으면 대기점으로 복귀합니다. 구역을 나가야 하는 추격은 하지 않습니다.
- 닌자는 기능팀의 후속 지시에 따라 **강한 단일 사용 타워 암살병**으로 표현합니다. 생산 완료 → 타워형 표적 하나 확정 → 접근 → 기존 공격 주기로 공격 → 기능팀의 소모 판정 순서입니다. 공격력 계수는 기능팀의 계약을 따릅니다.
- 앞서 제안한 닌자의 엄폐 대기·표적 소멸 후 복귀·재사용·추격 없는 제한 반격은 후속 기능 지시로 대체되었습니다. 이를 현재 동작으로 표시하거나 별도 기능으로 추가하지 않습니다.
- 기능 코드는 이동·표적 선정·공격 준비·발사·피해·치료·취소·사망·소모를 소유합니다. 표현 코드는 전달받은 상태와 실제 사건을 표시합니다.

## 장도병 설계도와 이동 경계

설계도에는 방어 경계, 내부 접근 통로, 대기·복귀점, 인식 범위, 병사의 점유 면적을 각각 표시합니다. **인식 범위 안에 있다는 사실만으로 접근하거나 타격할 수 있는 것은 아닙니다.** 표적까지 접근하는 전 경로와 실제 점유 면적이 구역 및 지형의 통행 조건을 만족해야 합니다. 구역 내부에서 사거리가 닿는 표적은 기능 판정을 따르며, 표적 자체가 경계 밖에 있다는 이유만으로 판정을 새로 정의하지 않습니다.

현재 기능 코드의 대응 항목은 다음과 같습니다. 구체적인 Stage 01 구역 데이터는 새 맵 설계에서 별도로 결정합니다.

| 기능 입력·판정 | 표현·설계 책임 |
| --- | --- |
| `guardZone.center` / `radius` / `polygon` | 기능팀이 정한 원 또는 다각형 방어 경계를 같은 좌표로 표시합니다. 인식 원과 구분합니다. |
| `guardZone.waypoints`, `guardTrail`, `guard_path()` | 설계 통로와 실제 이동·복귀 경로를 연결합니다. 도면의 선을 근거로 새로운 이동 명령을 만들지 않습니다. |
| `occupancyRadius`, `guard_point_inside()`, `_guard_segment_safe()` | 중심점뿐 아니라 병사 점유 면적과 이동 구간 전체의 여유를 반영합니다. 돌진도 같은 경계를 따릅니다. |
| `guard_target_valid()` | 생존·시야·기지 공격자 역할·인식 범위·경로·타격 조건을 통과한 대상만 교전 대상으로 표시합니다. |
| `movementBlocked` | 경로가 막혔는데 걷거나 돌진하는 것처럼 표시하지 않습니다. 선택 정보에 접근 실패의 실제 이유를 연결합니다. |

제품 화면의 범위·통로 표시는 배치, 선택, 관련 명령 확인 등 필요한 순간에만 노출합니다. 비선택 병사에 상시 범위 원을 켜지 않습니다.

## 닌자 단일 사용 임무

타워형 표적은 현재 `is_tower_attacker()`의 기능 판정을 따릅니다. `combatRole == "emplacement_assault"`, `fortification`, `stationaryEnemy`, 진입 상태 등의 실제 데이터로 결정하며 일반 보병이나 배경 구조물의 외형으로 대신 판단하지 않습니다. 표적 확정 이후 임의로 다른 타워나 일반 보병을 사냥하는 연출을 추가하지 않습니다.

현재 소스에 있는 `priorityTargetId`, `ambush_approach`, `engaged`, `consumed`를 상태 연결에 사용합니다. 상태 이름에 `ambush`가 남아 있어도 엄폐 대기·복귀 정책을 뜻한다고 해석하지 않습니다.

기능팀은 표적 파괴·소멸·무효·접근 불가, 또는 생산 시 표적 부재에 대해 소모를 판정하고 다음 사건을 보냅니다.

```text
unit_consumed { actorId, targetId, position, consumeReason }
```

표현은 **이 사건을 수신한 뒤** 해당 병사의 퇴장·페이드와 임무 종료 이유를 표시합니다. 페이드 완료나 타이머가 소모를 결정하지 않습니다. 소모에 환불, 사망·시체, 별도 보상을 붙이지 않습니다. 실제 타워 파괴 보상은 기존 기능 판정과 구분합니다.

## 선택 정보에서 정지 이유 구분

| 표시 | 연결할 근거 |
| --- | --- |
| 대상 없음 | 기능이 유효 표적 부재를 확인한 경우입니다. 닌자의 `no_target`은 임무 종료 사건의 이유로 표시하며 가짜 대기 상태를 유지하지 않습니다. |
| 접근 불가 | 기능 경로 판정 또는 실제 `movementBlocked`를 근거로 표시합니다. 닌자의 `unreachable`은 소모 사건에 연결합니다. |
| 공격 준비 중 | 아직 방출되지 않은 실제 `attackPlan`과 `releaseTime`에 연결합니다. 단순 재생 포즈로 공격 준비를 추정하지 않습니다. |
| 복귀 중 | 장도병의 실제 `guard_return` 등 기능 복귀 상태에 연결합니다. 닌자에게는 적용하지 않습니다. |
| 임무 종료 · 소모 | 실제 `unit_consumed` 수신 시에만 표시합니다. `consumeReason`과 표적 ID를 사용합니다. |

사망·소모·취소를 먼저 처리하고, 살아 있는 병사의 복귀·접근 실패·공격 준비·표적 부재를 표시합니다. 기능이 이유를 구분해 제공하지 않은 순간에 외형만으로 세부 이유를 만들어 내지 않습니다.

## 8개 병종의 기본 모션

| 병종 | 필요한 흐름 | 확인점 |
| --- | --- | --- |
| 궁병 | 경계 → 조준·활 당김 → 발사 → 회수 | 활시위 해제와 실제 화살 출발이 일치합니다. |
| 창병 | 집결·행군 → 정지·대치 → 찌르기 → 회수 → 행군 재개 | 실제 이동·정지·공격 방향이 일치합니다. |
| 사무라이 | 행군 → 대치 → 베기 → 회수 | 몸·무기·실제 표적의 방향이 일치합니다. |
| 조총병 | 고정 경계 → 조준 → 발사·반동 → 재장전 표현 | 기존 공격 주기를 유지하며 실제 발사에 반동을 연결합니다. |
| 장도병 | 경계 → 방어 구역 내부 접근 → 장도 교전 → 원위치 복귀 | 기존 돌진을 포함한 전 경로와 점유 면적이 경계를 준수합니다. |
| 승병 | 고정 대기 → 치료 준비·시전 → 회수 | 실제 치료 대상과 회복 순간을 표시합니다. 현재 기능의 HP 회복은 치료 몸짓 시작과 동시에 발생합니다. |
| 기마 무장 | 기마 이동 → 교전·기존 돌격 → 이동 재개 | 말의 발걸음과 실제 이동 속도·거리를 맞춥니다. |
| 닌자 | 생산·단일 표적 확정 → 접근 → 기존 주기 타격 → 소모 사건 후 퇴장 | 타워 암살 임무만 표시하며 엄폐 대기·복귀·재사용·반격 제안을 적용하지 않습니다. |

실제 적군에도 대기·이동·공격·피격·사망과 무기·접지를 같은 원칙으로 연결합니다. 적의 공격 준비는 `rangedPlan` / `counterPlan`, 방출은 실제 적군 `shot`, 피격·사망은 기존 HP 및 사망 배우 상태를 사용합니다. 적군의 외형 종류를 근거로 새로운 공격·AI·피해를 만들지 않습니다.

## 실제 발생과 모션의 연결

- 이동은 실제 위치 변화와 `animation == "walk"`, 공격 준비는 `attackPlan`, 방출은 기존 `releaseTime`과 실제 `shot`을 기준으로 연결합니다. 피해 도착은 실제 `hit`, 피격은 `hitClock` 및 해당 사건을 사용합니다. 공격 전환이 취소되거나 계획이 비면 준비 표현을 중단합니다.
- `heal` 사건의 `victimId`, `healAmount`, `hpBefore` / `hpAfter`가 치료 대상·회복의 기준입니다. 현재 `UnitSkills._heal()`은 HP를 먼저 반영하고 같은 순간에 `animation = "heal"`과 사건을 만듭니다. 연출 후반에 다시 회복시키거나, 준비 포즈를 위해 회복 시점을 미루지 않습니다.
- 모션 재생기는 피해·발사체·범위 피해·지속 피해·회복을 생성하지 않습니다. 기존 연사·범위·지속 피해는 개별 실제 발생에 표현을 연결합니다.
- 피격 표현은 기존에 없던 경직·넉백을 만들지 않습니다. 조총 재장전 길이로 공격 속도를 바꾸지 않습니다. 발을 앞으로 내딛는 공격 포즈도 실제 위치·점유 경계를 벗어나게 이동시키지 않습니다.
- 사망은 기존 `hp`, `death` / 사망 배우 상태를 표시합니다. 닌자 소모는 별도의 `unit_consumed` 사건을 표시합니다. 사건 중복 수신이나 화면 갱신 때문에 피해·퇴장을 중복 생성하지 않습니다.

## 시각 검증 완료 조건

고각 전장 화면에서 8개 병종과 경계·이동·공격·피격·사망·소모를 식별할 수 있어야 합니다. 실제 웨이브의 평지·경사·정지·회전 구간을 연속 재생하여 발 접촉, 이동 거리와 발걸음, 무기·구조물 관통, 몸·무기·타격 방향을 확인합니다. 장도병의 표적 소멸·복귀·경로 실패·돌진 경계와 닌자의 단일 표적·소모 사건도 같은 실행에서 확인합니다.

이 문서와 SVG의 작성·구문 검사는 설계 자료 검증입니다. 고정 포즈 캡처, 코드 검사 또는 개념도 렌더링만으로 실제 이동·자연 웨이브 시각 검증을 완료했다고 판단하지 않습니다. 실제 실행 증거와 미확인 범위는 통합 담당자의 검증 결과에 따릅니다.

소스 대응: `native/ground_combat.gd`, `native/game.gd`, `native/unit_skills.gd`, `native/sengoku_actor_3d.gd`. 기능팀이 병행 수정하는 파일이므로 통합 시 최종 상태·사건 이름을 다시 확인합니다.
